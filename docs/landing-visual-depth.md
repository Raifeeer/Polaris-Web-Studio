# Iteración de profundidad visual

La landing necesitaba una capa visual entre el hero y los mockups. Se definió una dirección de escenas editoriales: el asset del taller muestra un entorno real de trabajo con laptop y wireframes, dejando espacio negativo útil para acompañar copy; el asset de proceso usa papel, vidrio, grillas y planos de color para representar cómo una intuición se convierte en estructura; el asset del ecosistema se reserva como atmósfera de fondo para conectar visualmente las capas de Polaris.

Los assets no contienen copy legible ni marcas inventadas. Su función es contextual: taller para estrategia, materiales para proceso y horizonte luminoso para ecosistema.

Los tres assets se convirtieron a WebP optimizado: aproximadamente 110 KB para el taller, 259 KB para proceso y 50 KB para el horizonte. El build de Vite terminó correctamente. La vista desktop volvió a abrirse sin errores de página tras conectar las rutas públicas de los assets.

La revisión visual de desktop muestra que la sección de sistema dejó de ser plana: el mapa explica la estructura y la escena del taller aporta una segunda capa editorial claramente relacionada. La captura automatizada estuvo parcialmente cubierta por el banner de cookies, por lo que la siguiente comprobación cerrará ese banner y enfocará el proceso y el ecosistema.

Se cerró el banner de cookies en la sesión de prueba y se enfocó el proceso. La captura limpia se tomó sin overlays temporales para evaluar la relación entre la imagen vertical y la secuencia de pasos.

La captura limpia del proceso confirma el objetivo: la imagen vertical introduce textura, materialidad y contraste; los pasos permanecen legibles y conectados por una línea de recorrido. La composición se siente más como una secuencia editorial que como una cuadrícula de tarjetas repetidas.

El proceso también se probó en viewport móvil de 390 × 844 px con captura de dispositivo para revisar el orden vertical y el recorte del asset editorial.

La revisión móvil confirma una continuidad más rica: el hero conserva su jerarquía y el mockup comienza a aparecer como siguiente escena, sin desbordamiento horizontal ni pérdida del CTA. La imagen de proceso está preparada para continuar en flujo vertical.
